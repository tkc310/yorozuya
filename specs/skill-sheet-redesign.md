## 0. 改善の方針

採用担当者（業務委託の書類選考）は 1 名あたり数十秒〜1 分程度で「面談に進めるか」を判断する。判断に使う情報のうち、次の 3 つは **1 ページ目の上半分で読み取れること**を目標にする。

1. どんな人か（氏名・肩書・経験年数）
2. 条件が合うか（稼働開始時期・稼働量・リモート可否・契約形態）
3. 求めるスキルを持っているか（ハイライト・主要スキルと年数）

そのうえで、シート全体の並びは**面談での説明順（自己紹介 → 経歴紹介）**に合わせる。前半をプロフィール（基本情報 → 強み → 保有技術 → 資格・語学 / リンク → 自己 PR）、後半を職務経歴（サマリー → 詳細）とし、自己 PR から職務経歴サマリーへそのまま話をつなげられるようにする。

上部の項目は §2-1 の 3 つのまとまり（人物 / 基本情報 / 強み）に MECE に振り分け、**どの項目も 1 か所にだけ出す**。

## 1. ページ構成（最優先）

### 1-1. 新しい並び

| 順  | まとまり（`Block.group`） | ブロック                            |
| --- | ------------------------- | ----------------------------------- |
| 1   | `profile`                 | ヘッダー（人物）＋ 基本情報の表     |
| 2   | `profile`                 | 強み（ハイライト ＋ 主要スキル）    |
| 3   | `profile`                 | 保有技術                            |
| 4   | `profile`                 | 資格・語学 ／ リンク（2 カラム）    |
| 5   | `profile`                 | 自己 PR                             |
| 6   | `career`                  | 職務経歴サマリー（一覧）            |
| 7   | `career`                  | 職務経歴詳細（1 案件 = 1 ブロック） |

- `Preview/index.tsx` の `sheetBlocks()` を上記の順に組み替える。
- **強制改ページはしない**。上から詰めて流し、入りきらないブロックだけ次ページへ送る（現状の「まとまりが変わったら改ページ」は廃止）。強制改ページを残すと、自己 PR だけのページ（下 3/4 が空白）ができてしまうため。
- 代わりに「見出しだけがページ末尾に取り残されない」規則を入れる。`MeasuredBlock` に `keepWithNext: boolean` を追加し、真のブロックは次のブロックと同じページに置く（職務経歴サマリーの見出し、職務経歴詳細の見出し）。
- **職務経歴サマリーは行単位のブロックに分割**し、ページをまたいだら送った先でも表のヘッダー行を繰り返す（現状は表全体が 1 ブロックのため、案件数が多いと 1 ページを超えたまま描画される）。
  - 実装案: `career-list-head`（見出し＋注記、`keepWithNext`）と `career-row-{id}` を別ブロックにし、ページの先頭に `career-row-*` が来たら `<thead>` を出す。
- 受け入れ基準: `sample/dummy-skill-sheet.json`（8 案件）で、1 ページ目に基本情報〜資格・語学 / リンク、2 ページ目に自己 PR と職務経歴サマリー、3 ページ目以降に職務経歴詳細が並び、合計 5 ページ以内になること（`proposed.pdf` がこの割り付け）。

### 1-2. ランニングヘッダー / フッター

- 2 ページ目以降の上端に 1 行のランニングヘッダーを付ける: 左「スキルシート｜{氏名}」、右「更新日 YYYY/MM/DD」。7.5pt・`#57606a`、下に 0.5pt の罫線。
- フッターは現状どおり右下に「n / N」。
- `pagination.ts` の `PAGE_BODY_HEIGHT_MM` はヘッダー分（約 6mm）を差し引いた値をページごとに使う（1 ページ目はヘッダーなし）。`paginate()` に「ページごとの上限」を渡せるよう引数を配列または関数に変える。
- `pagination.test.ts` に、ヘッダーあり / なしの上限・`keepWithNext`・強制改ページがなくなったことのテストを追加する（既存の「まとまりが変わると改ページ」のテストは削除）。

### 1-3. タグ（共通部品）

抜粋案件と主要スキルの印は、記号（★・●・(※)）を使わず**文字入りのタグ**に統一する。記号は意味を覚えてもらう必要があり、白黒印刷やコピーで潰れやすいため。

| タグ   | 用途                                                    | 見た目                                                                               |
| ------ | ------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `抜粋` | 高難易度な案件やスキルアップできた案件（`Career.hard`） | 7pt 太字、文字 `#8a5a00`、背景 `#fff8e1`、枠 0.5pt `#d4a017`、角丸 0.6mm、左右 1.2mm |
| `主要` | 主要スキル（`Skill.featured`）                          | 7pt 太字、文字 `#1f3a5f`、背景 `#eef3f8`、枠 0.5pt `#7b9cc0`、同上                   |

- `Preview/styles.ts` に `badge` レシピ（`variant: "excerpt" | "main"`）として定義し、一覧・詳細・保有技術・注釈で同じものを使う。
- 名前の直後に左 1.5mm 空けて置き、折り返さない（`white-space: nowrap`）。
- タグを使う欄の見出し横の注釈には、**同じタグをそのまま入れて**意味を書く（例: 「`抜粋` は高難易度な案件やスキルアップできた案件など」）。

## 2. プロフィール

`proposed.pdf` の 1〜2 ページ目が完成イメージ。並びは「ヘッダー（人物）→ 基本情報 → 強み → 保有技術 → 資格・語学 / リンク → 自己 PR」。

### 2-1. 上部の情報の整理（MECE）

上部の項目を、採用担当者が確認する順に 3 つのまとまりに分ける。まとまりどうしで重ならず、上部の項目はどれかに必ず入る。どの項目も 1 か所にだけ出す。

| 順  | まとまり | 担当者の問い             | 項目                                                             | 表示場所             |
| --- | -------- | ------------------------ | ---------------------------------------------------------------- | -------------------- |
| ①   | 人物     | 誰か・どのレベルか       | フリガナ・氏名・年齢・性別・肩書・経験年数                       | ヘッダー（§2-2）     |
| ②   | 基本情報 | 契約できるか・経歴の前提 | 稼働開始・稼働量・希望単価・勤務形態・最寄駅・契約形態・最終学歴 | 基本情報の表（§2-3） |
| ③   | 強み     | 何ができるか             | ハイライト・主要スキル                                           | 基本情報の下（§2-4） |

- 最寄駅は「出社・常駐が必要なときに通えるか」の判断材料として基本情報に入れる。
- 所属（フリーランス / 法人）と希望雇用形態は、どちらも契約の結び方の話なので「契約形態」1 項目にまとめる。
- 更新日は人物ではなく書類の情報なので、ヘッダー最上段の右端に小さく置く（どのまとまりにも入れない）。
- 表の中に「稼働条件」「個人属性」のような分類ラベルは付けない（項目数が少なく、ラベルの列が幅と注意を取るだけのため）。並び順で優先度を表す。

### 2-2. ヘッダー ＝ ① 人物（現状の `masthead` を置き換え）

```
スキルシート                                                    更新日 2026/10/18
新究羅 理定（シンギュラ リティ）   36歳 ｜ 男性
デザインエンジニア / フロントエンドテックリード ｜ 経験 11年11ヶ月
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

- 最上段: 左に「スキルシート」（7.5pt・字間 0.2em・アクセント色の小見出し）、右に「更新日 YYYY/MM/DD」（8pt・灰色）。
- 2 段目: 氏名を 20pt・太字で最も大きく出す。
  - 氏名の直後（左 1.5mm）に **フリガナ（新規項目 `nameKana`）** を全角括弧で囲んで `（シンギュラ リティ）` と出す。9pt・標準ウェイト・灰色 `#57606a`・字間 0.05em、氏名とベースライン揃え。未入力なら括弧ごと出さない。
  - 同じ行のさらに右（間 4mm）に **年齢・性別** を 10pt 太字で並べる（年齢と性別の間は 0.75pt の縦線）。表示オフ・未入力のものは出さない。
- 3 段目: **肩書（新規項目 `title`）** と **経験年数** を 10.5pt・太字で並べる。肩書はアクセント色、経験年数は本文色で、間を 0.75pt の縦線で区切る。経験年数は表示オフなら出さない。
- `nameDisplay` がイニシャルのときは、氏名をイニシャルにし、フリガナは出さない。
- 下線は 1.5pt・アクセント色。

### 2-3. 基本情報の表 ＝ ②（現状の `facts` を置き換え）

見出し「基本情報」の下に、分類ラベルのない 3 列のグリッドを置く。**背景の塗り・外枠・縦の罫線は使わない**。

```
稼働開始               稼働量                 勤務形態
2026年12月〜           週4日（月130h程度）     フルリモート希望（月1〜2回の出社可）
──────────────      ──────────────      ──────────────
最寄駅                 契約形態               最終学歴
東急東横線 学芸大学駅    業務委託（フリーランス）  美術大学 情報デザイン学科 卒業
──────────────      ──────────────      ──────────────
```

- 各マスは項目名（7pt 太字・`#57606a`）と値（9pt 太字・本文色）の 2 行。上下の余白は 1.3〜1.4mm。
- マスの下にだけ 0.5pt `#e1e5ea` の区切り線を引く。列の間は線ではなく 6mm の余白で分ける（線が列ごとに途切れるので、縦線なしでも列が読み取れる）。
- 塗りをやめる理由: 見出しの下線・ヘッダーの下線とあわせて線と面が重なり、ノイジーになるため。強調は「項目名は小さく灰色、値は太字」の文字の対比だけで足りる。背景色は「強み」以下で使わないので、ページ上部がすっきりし、ヘッダーの氏名に視線が集まる。
- 並び順は担当者が確認する順に固定する: **稼働開始 → 稼働量 → 希望単価 → 勤務形態 → 最寄駅 → 契約形態 → 最終学歴**（いつから → どれだけ → いくらで → どこで → どう契約するか → 経歴の前提）。
- 表示オフ・未入力の項目は詰める。最後の行が 3 マスに満たないときは空のマスを残してよい（罫線は揃える）。すべて空なら見出しごと出さない。
- 「契約形態」は `desiredEmployment` と `affiliation` をまとめて `業務委託（フリーランス）` の形で出す（片方だけなら片方だけ）。
- 「稼働開始」「勤務形態」「希望単価」は新規項目（§5）。希望単価は初期オフ。

### 2-4. 強み ＝ ③ ハイライト ＋ 主要スキル（2 カラム、左 1.25 : 右 1）

**左: ハイライト**（新規項目 `highlights`、§5）

- 最大 3 件の箇条書き。行頭は 1.6mm の丸（アクセント色）。
- 現状の「得意な技術」「得意な業務」はこれに置き換える。
- 職務経歴サマリーが 2 ページ目に移るため、直近の実績もここで 1 件は触れるよう、フォームのプレースホルダで案内する（例: 「直近の案件で〜を担当し、〜を達成」）。

**右: 主要スキル**

- 保有技術のうち「主要」に指定したもの（新規 `Skill.featured`、最大 8 件）を経験年数の長い順に並べる。
- 1 行 = 技術名（太字）／横棒（経験年数に比例、色 `#7b9cc0`、高さ 2.4mm）／年数（右寄せ・太字）。この欄はすべて主要スキルなので `主要` タグは付けない。
- 年数の表記は §2-5 の丸め規則に従う。
- 主要スキルが 0 件のときは、経験年数の上位 6 件を自動で出す。

### 2-5. 保有技術（現状の `Skills` を改修）

- 見出し横の注釈: 「経験年数は 0.5 年単位｜`主要` は主要スキル」（`主要` は §1-3 のタグそのもの）。
- タグ表示をやめ、**グループごとの縦リスト**を **3 段の段組み（`column-count: 3`、段間 5mm）** で上から詰めて並べる。
  - 3 列のグリッドにすると行ごとに高さが最も高いグループに揃い、短いグループの下が空くため、段組みにする。グループは `break-inside: avoid` で段をまたがせず、グループ間は 3mm。
  - グループは入力順に「1 段目の上 → 下 → 2 段目 …」と流れる。
  - グループ名: 8.5pt 太字・背景 `#eef3f8` の帯。
  - 各行: 左に技術名、右に年数（右寄せ・等幅数字 `font-variant-numeric: tabular-nums`）、行間は 0.5pt の点線。
  - 主要スキル（`featured`）は技術名を太字にし、直後に `主要` タグを付ける。
- グループ内は**経験年数の長い順**に並べる（同年数は入力順）。フォームで並べ替えたい人向けに、並び順を「入力順 / 年数順」で切り替える設定を `SheetInput` に持たせてもよい（初期値は年数順）。
- ブロック全体を 1 ページ内に収める（途中で改ページしない）。
- **年数の丸め**: 選考ではヶ月単位は不要なので 0.5 年刻みで出す。
  - 12 ヶ月未満 → `1年未満`、それ以上 → `floor(月数 / 6) / 2` 年（例: 8年7ヶ月 → `8.5年`、10年 → `10年`）。
  - 職務経歴の期間（`1年8ヶ月`）とヘッダーの経験年数は従来どおりヶ月まで出す。
  - 実装は `shared/features/skill-sheet/sheet.ts` に `formatSkillYears(duration)` を追加し、テストを書く。

- 本文は現状どおり改行保持。プロフィールの最後に置き、そのまま職務経歴サマリーへ続ける。

## 3. 職務経歴サマリー（現状の `CareerList` を改修）

見出し「職務経歴サマリー」の横に小さく「新しい順｜`抜粋` は高難易度な案件やスキルアップできた案件など」と添える（`抜粋` は §1-3 のタグそのもの）。現状の 2 つの長い注記は廃止し、並行案件の注記は期間の重なりがあるときだけ同じ行に「期間の重なりは並行案件」と追記する。抜粋案件が 1 件もなければ `抜粋` の注釈は出さない。

列構成:

| 列              | 幅   | 内容                                                                                |
| --------------- | ---- | ----------------------------------------------------------------------------------- |
| No              | 6mm  | 番号（太字・アクセント色・中央）                                                    |
| 期間            | 19mm | `2024/01 –` ／ `2025/03` ／ `1年2ヶ月`（3 行、期間の長さは灰色）                    |
| 案件 / 業務概要 | 残り | 1 行目: 案件名（太字）＋ 抜粋案件なら `抜粋` タグ、2 行目: 一覧用の概要（灰色寄り） |
| 役割            | 36mm | 担当職種、2 行目に雇用形態（灰色）                                                  |
| 主な技術        | 40mm | 案件の「技術・環境」の先頭 4 件を `/` 区切り（7.6pt）                               |

- 「雇用形態」列は廃止し、役割の 2 行目にまとめる（ほとんどの行が同じ値で、列を割く価値が低い）。
- 期間は `YYYY/MM` 表記にして幅を節約する（詳細カードも同じ表記に揃える）。
- ヘッダー行は背景アクセント色・白文字。行は 0.5pt の下罫線のみ（縞模様はやめる。罫線のほうが白黒印刷で安定する）。
- 縦位置は `top` 揃え（現状 `middle` は行の高さが不揃いなとき視線が迷う）。

## 4. 職務経歴詳細（`DetailCareer` を改修）

### 4-1. カードヘッダー

- `No.1` のテキストを、直径 5.5mm の丸に白抜き数字（アクセント色）に変える。
- 案件名 10pt 太字。抜粋案件は案件名の直後に `抜粋` タグ（§1-3）。
- 右端に `2025/04 – 現在` ＋ 太字・アクセント色で `1年6ヶ月`。

### 4-2. メタ情報行

- 現状の 2 行（グリッド）を 1 行のインライン表記にする: `役割 … ｜ 契約 … ｜ 体制 … ｜ 手法 …`。項目名は灰色。長いときは自然に折り返してよい。

### 4-3. 本文（左カラム）

- 「概要」の見出しは外し、概要文を**太字のリード文**として先頭に置く。
- 「担当業務」は見出し（7.2pt 太字・アクセント色）＋ 本文。
- 「注力した課題・成果」→ 見出しを「成果」に短縮し、本文を**背景 `#f3f7fb`＋左 1mm のアクセント色の線**で強調する。選考側が最も見たい数値実績を目立たせるため。

### 4-4. サイド（右カラム、幅 56mm → 50mm、背景 `#fafbfc`）

- 技術・環境 / ツールはタグ枠をやめ、`/` 区切りのテキストにする（7.9pt）。枠付きタグは行数が増え、密度が下がるため。
- 担当工程は 4×2 の表をやめ、**4 列 2 段のチップ**にする。
  - 担当した工程: アクセント色の塗り・白文字・太字。担当していない工程: 枠のみ・薄い灰色文字。
  - ラベルは現場で通じる略称にする（`PHASES` に表示用の短縮名マップ `PHASE_SHORT` を追加）:

    | 工程 | 要件定義 | 基本設計 | 詳細設計 | 実装 | ユニットテスト | 結合テスト | E2Eテスト | 保守運用 |
    | ---- | -------- | -------- | -------- | ---- | -------------- | ---------- | --------- | -------- |
    | 表示 | 要件     | 基本     | 詳細     | 実装 | **単テ**       | **結テ**   | E2E       | 保守     |

  - 各チップの `aria-label` には正式名（「ユニットテスト」など）を入れる。
  - 白黒印刷でも塗り / 枠で判別できること。

### 4-5. 受け入れ基準

- サンプル 8 案件で詳細が 3 ページ（1 ページ 3 案件）に収まる。
- 「職務経歴詳細」の見出しが前ページの末尾に取り残されない。
