# 作業報告書 指示書

対象リポジトリ: `tkc310/yorozuya`（新機能）
主な対象ファイル:

- `src/routes/work-report.tsx`（ルート `/work-report`）
- `src/components/features/WorkReport/**`（画面・xlsx の書き出し）
- `src/shared/features/work-report/**`（形・祝日・集計の計算）
- `src/server/db/schema.ts` / `src/server/db/migrations/0019_work_report.sql` / `src/server/features/work-report/**`（保存と読み込み）

画面とデータの設計案は、実装前に依頼者に確認を取った。

---

## 0. 目的

業務委託で精算幅（例: 140〜180h）のある契約を持つ人が、月の途中で「下限まであと何時間か」「残り何日あるか」を確かめながら稼働を記録し、月末にそのまま提出用の作業報告書を書き出せるようにする。

## 1. 画面

| 部分       | 内容                                                                                                                                        |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 見出し     | 「作業報告書」、稼働日設定・表示中の月の xlsx 書き出し・1 年分の書き出しのボタン                                                            |
| 月のタブ   | 前後の年への移動と、1〜12 月のタブ。開いたときは今月。今月のタブには下線                                                                    |
| 日ごとの表 | 日付（祝日名・休み）、区分（通常・休み・稼働）、予定、開始、終了、休憩（分）、実働、作業内容、「予定で埋める」                              |
| 進み具合   | 精算幅の下限・上限、実績、実績と見込みと精算幅のメーター、下限まで・上限まで・残り稼働日・下限に必要な 1 日あたり・見込み合計・今月の稼働日 |

- 入力は欄を離れたときに保存する。開始・終了は `9:30`・`930`・`9` のどれでも読み、保存後は `9:30` に整える。日をまたぐ終了は `25:00` のように書く
- 読めない入力は保存せず、その行にエラーを出す
- 狭い画面では進み具合を表より先に出す。表は横にスクロールする
- 「予定で埋める」は、既定の開始・休憩と、その日の予定時間から開始・終了・休憩を入れる

## 2. 稼働日設定（ダイアログ）

- 曜日ごとの予定時間（h）。0 か空の曜日は休み
- 祝日は休みにする（既定は真）
- 「予定で埋める」の既定の開始と休憩
- 書き出しに載せる氏名・提出先・案件名

## 3. 計算（`report.service.ts`）

- 稼働日: 日ごとの切り替えが「通常」なら、曜日の予定が 0 より大きく、「祝日は休み」のときは祝日でない日。「休み」「稼働」に切り替えた日はそれに従う
- 休みの曜日を「稼働」に切り替えた日の予定は、曜日の予定のうち最も長いもの
- 実働 = 終了 − 開始 − 休憩（開始か終了が無ければ未入力）
- 残り稼働日数 = 今日以降の稼働日のうち、実働が未入力の日。過去の月は 0、先の月は月の稼働日すべて
- 下限まで = max(0, 下限 − 実績)、上限まで = 上限 − 実績（負なら超過）
- 下限に必要な 1 日あたり = 下限まで ÷ 残り稼働日数（切り上げ）
- 見込み = 実績 + 残り稼働日の予定の合計。精算幅と比べて「届かない・収まる・超える」を出す
- 時間はすべて分の整数で持ち、画面は時間で小数 1 桁

## 4. 祝日

内閣府の CSV を正本にし、取得と配信は [tkc310/jp-holidays](https://github.com/tkc310/jp-holidays) が受け持つ（ADR 0013）。

| 段階               | すること                                                                                                                                        |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 取得と配信         | jp-holidays の GitHub Actions が毎年 3/1 に CSV を取得し、`https://tkc310.github.io/jp-holidays/holidays.json` で配る                           |
| 取り込み（必要時） | 取り込み済みのデータが開いた年を含まないときだけ取得し、SQLite の `holidays`・`holiday_feeds` を置き換える。同じ起動の中で同じ年は 1 回だけ試す |
| 推定               | 取り込めていない年は祝日法のルール（`holiday.service.ts`、2000〜2099 年）で推定し、画面に「推定」と出す                                         |

## 5. 精算幅

月ごとに下限・上限を持つ。設定の無い月は、それより前で最も新しい月の値を引き継いで見せる（保存は入力したときだけ）。

## 6. 保存（SQLite）

| 表                     | 内容                                                                       |
| ---------------------- | -------------------------------------------------------------------------- |
| `work_report_settings` | 1 行だけ（id `default`）。曜日ごとの予定・祝日の扱い・既定の開始と休憩など |
| `work_report_months`   | 年月ごとの精算幅                                                           |
| `work_report_days`     | 入力した日だけ。空に戻した日は行ごと消す                                   |
| `holidays`             | 取り込んだ祝日（日付 → 名称）                                              |
| `holiday_feeds`        | 取り込んだ範囲（最初と最後の年）と取り込んだ日時。1 行だけ                 |

書き込みは `src/server/features/work-report/repository.ts` だけで行う。

## 7. xlsx の書き出し

- 依存パッケージを足さず、`xlsx.service.ts` で最小限の Office Open XML を組み立て、無圧縮の ZIP で包む
- 1 か月 1 シート（シート名は「11月」など）。見出しに対象月・氏名・提出先・案件名・精算幅、日ごとの行に日付・曜日・区分・開始・終了・休憩(h)・実働(h)・作業内容、末尾に合計（`SUM`）と稼働日数（`COUNT`）。式には計算済みの値も入れる
- ファイル名は `work-report-2026-11.xlsx`（1 年分は `work-report-2026.xlsx`）。日本語のファイル名はブラウザによって置き換わるため英数字にする
- Excel と Google スプレッドシートでそのまま開ける
