# 0011 PDF は手元のサーバが Chrome で作る（ブラウザの印刷は残す）

- 日付: 2026-11-18
- 状態: 採用

## 背景

スキルシートの PDF は、ブラウザの「印刷 / PDF 保存」で作っていた。ブラウザや OS の印刷ダイアログを通すため、余白・倍率・ヘッダーとフッターの設定や、ブラウザの印刷エンジンの違いで、同じシートでも PDF の見た目や改ページが変わることがあった。

## 決定

- 「PDF をダウンロード」を足し、手元のサーバ（`make dev` か `.app` の Bun）が PDF を作る
- サーバは Bun 組み込みの `Bun.WebView`（Chrome のバックエンド）で印刷用の画面 `/skill-sheet/print` を開き、DevTools Protocol の `Page.printToPDF` で PDF にする。用紙と余白は画面の `@page` に従う（`preferCSSPageSize`）
- ブラウザは、macOS では Google Chrome・Chromium・Microsoft Edge・Brave の順に `/Applications` と `~/Applications` から探す。`BUN_CHROME_PATH` があればそれを使う。動いている Chrome には繋がず、いつも別の Chrome を裏で立ち上げる
- 開けるのは手元のサーバ（127.0.0.1・localhost・::1）の画面だけ
- PDF にするのは保存済みの内容。シートのコマンドを TanStack Query の同じ `scope` に並べ、ボタンを押したときの保存が済んでから PDF にする
- Chromium 系のブラウザが無いときはメッセージを出し、これまでの「印刷 / PDF 保存」を使ってもらう

## 理由

- 画面のプレビューと同じコンポーネントと印刷用の CSS をそのまま使えるので、改ページや見た目を二重に作らずに済む（プレビューの割り付けを直せば PDF も直る）
- 依存パッケージが増えず、`.app` も大きくならない
- PDF を JS で直接組む方法（`@react-pdf/renderer` など）は、レイアウトを別に作り直すことになり、日本語フォントの同梱も要る
- Chromium を `.app` に同梱する方法は、どの Mac でも同じ結果になるが、1 アーキテクチャあたり約 150MB 増える。必要になったら、同梱したバイナリのパスを `src/server/lib/pdf.ts` で渡せば切り替えられる

## 影響・トレードオフ

- Chromium 系のブラウザが入っていない Mac では使えない（従来の印刷は使える）
- ブラウザの版によって、文字の描画にわずかな違いが出ることはある。割り付けはプレビューで決まるので、改ページは変わらない
- PDF は保存済みの内容から作るため、経歴のダイアログで編集中（未保存）の内容は入らない
