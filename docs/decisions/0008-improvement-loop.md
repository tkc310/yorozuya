# 0008 AI 駆動開発の改善ループ（バックログ・ログ・ADR・改善スキル）を置く

- 日付: 2026-10-19
- 状態: 採用

## 背景

開発の多くを AI エージェントと進めている。会話で受けた指摘（文言・見た目・手順の失敗）がその場で直るだけだと、別の会話で同じ失敗を繰り返し、判断の理由も残らない。

## 決定

[tkc310/8341-ui](https://github.com/tkc310/8341-ui/tree/main/docs) の仕組みに倣い、次を置く。

- `docs/improvement-loop.md`: 気づく → 記録する → 直す → 再発を防ぐ → 振り返る の手順と、問題の種類ごとに足す再発防止の対応表
- `docs/improvement/backlog.md`: 改善候補。`docs/improvement/log.md`: 直したことを 1 改善 1 行で記録
- `docs/decisions/`: ADR
- `docs/specs/`: 実装前に書く指示書（もとの `specs/` を移した）
- `.claude/skills/improve/SKILL.md`: エージェントが 1 件の改善を回す手順
- Issue テンプレート「改善提案」、PR テンプレートの log.md のチェック、AGENTS.md の「まず読むもの」「守ること」

## 理由

- 指摘を検査・テスト・ルールに変えれば、どのエージェント・どの会話でも同じ失敗を防げる
- ADR とログがあれば、後から来た人やエージェントが「なぜこうなっているか」を追える

## 影響・トレードオフ

- PR ごとに log.md を 1 行書く手間が増える
- ログとバックログは手で保守するので、古くなったらまとめて整理する
