# 0003 スキルシートを書類選考向けに作り直し、JSON を版 2 にする

- 日付: 2026-10-19
- 状態: 採用

## 背景

業務委託の採用担当者は 1 人あたり数十秒〜1 分で「面談に進めるか」を決める。従来のシートは、人物・条件・スキルが 1 ページ目の上半分で読み取りにくく、記号（★・●）の意味を覚えてもらう必要があった。

## 決定

- 並びを面談での説明順（基本情報 → 強み → 保有技術 → 資格・語学 / リンク → 自己 PR → 職務経歴サマリー → 詳細）にする
- 記号をやめ、文字入りのタグ（`抜粋`・`主要`）にする。選んだ案件のタグは「抜粋」で、注釈は「高難易度な案件やスキルアップできた案件など」
- 氏名のフリガナ・肩書・稼働条件などの項目を足し、書き出す JSON を版 2 にする。版 1 は読み込み時に版 2 に変換する
- 画面と印刷で同じ改ページになるよう、ブロックの高さを測って割り付ける

詳細は [`docs/specs/skill-sheet-redesign.md`](../specs/skill-sheet-redesign.md)。

## 理由

判断に要る情報を最初に見せると、書類選考を通りやすくなる。タグは白黒印刷やコピーでも潰れにくい。

## 影響・トレードオフ

- データベースに列と表を足した（マイグレーション `0018_skill_sheet_v2.sql`）
- 版 1 の JSON を読み込むテストを置き、互換を守る
- 「注力」のように案件ごとの取り組み方に差があると読める言い方は使わない
